## 核心概念图：从 Dense 到 CNN

```
┌── Dense ────────────────────────────────────┐
│                                               │
│  图像 ──Flatten──→ 784 个独立数字             │
│  每个像素 ←──→ 每个神经元  独立权重           │
│  参数 = 输入尺寸 × 神经元数（图像大就爆炸）    │
│  不知道像素之间的邻居关系                      │
│                                               │
└───────────────────────────────────────────────┘
                    ↓ 升级
┌── CNN ──────────────────────────────────────┐
│                                               │
│  图像 ──保持 2D 输入──→ 高 × 宽 × 通道        │
│  一个 3×3 卷积核 ──滑遍整张图──→ 复用同一组权重│
│  参数 = 卷积核大小 × 通道数（和输入尺寸无关）  │
│  保留了像素的空间邻居关系                      │
│  同一个特征出现在不同位置都能被识别（平移不变性）│
│                                               │
└───────────────────────────────────────────────┘
```

## Dense vs CNN 三角度对比

| 角度 | Dense | CNN |
|------|-------|-----|
| 每个神经元看到什么？ | 上一层的**全部**神经元 | 上一层的**一个局部窗口**（感受野） |
| 参数怎么共享？ | **不共享**——每个连接独立权重 | 一个卷积核在所有位置**滑动复用** |
| 空间位置信息 | **丢失**——Flatten 后不知道左上角和右下角原来是邻居 | **保留**——滑动时维持 2D 空间结构 |

### 参数效率——一个具体的震撼

32×32×3 图像 → Flatten 成 3072 维：

- Dense 第一层（假设 1000 个神经元）：3072 × 1000 + 1000 = **3,073,000** 个参数
- Conv2D(32, 3×3) 第一层：3×3×3×32 + 32 = **896** 个参数
- **差了约 3400 倍！**

而且 CNN 的参数量只取决于卷积核大小，和输入图尺寸无关。

### 什么时候用什么？

| 场景 | 选型 | 理由 |
|------|------|------|
| 10 个数值特征（年龄/收入） | Dense | 没有空间结构，不需要滑窗 |
| 256×256 卫星图判断有无云 | CNN | 2D 空间信息是关键 |
| 已提取好的 128 维特征向量 | Dense | 已经是 1D 特征，没有空间关系 |

## 反向传播——本周最重要的补充理解

前两周一直用 `model.fit()` 但没理解"训练"到底怎么发生的。

### 类比：调热水器

- 伸手试水温 = **前向传播**（输入 → 输出）
- "太冷了" = **计算误差**（loss）
- 拧热水旋钮 = **反向传播**（根据误差往回调整参数）

### 核心逻辑

```
输入 x → [w1] → h → [w2] → 预测 ŷ
                              ↓
                         真实值 y（标签）
```

- w2 离输出近，责任清楚：它的调整量好算
- w1 离输出远，但它通过影响 h 间接影响了 ŷ

反向传播 = **从输出端开始，沿着原路往回走，把误差按比例分配给每一层**

## 迁移学习——为什么必须先冻后微调？

这是我本周理解最深刻的一个点。

### 两阶段

```
阶段 1（特征提取）：
  base.trainable = False       ← 冻住全部基座
  model.fit()                  ← 只训练随机分类头
  目的：让分类头收敛到合理状态，梯度变小且方向明确

阶段 2（微调）：
  解冻 base 最后几个 block     ← 只解冻高层语义层
  learning_rate 降 10 倍       ← 小步更新
  model.fit()                  ← 同时训练分类头+基座后部
  目的：微调高层特征适配新任务
```

### 为什么不一开始就一起训？

随机初始化的分类头 → 预测基本是乱猜 → loss 巨大 → **反向传回巨大梯度**

这些巨大梯度如果传到预训练基座 → 会把 ImageNet 上几百小时算力找到的精密权重"一脚踹飞"

用类比说：一台精密调好的望远镜（预训练基座），你换了山寨目镜（随机分类头），一看糊的。如果你同时拧目镜和镜筒的螺丝，会把镜筒的精密校准也拧坏。正确做法：先锁死镜筒，只调目镜；目镜调清楚后再小心微调镜筒。

## 踩过的坑（第二周全）

| 坑 | 教训 |
|----|------|
| padding 理解不牢 | `same` = 输出尺寸不变（自动补零），`valid` = 不补零 |
| 数据增强顺序 | 增强层放在模型最前面，推理时自动关闭 |
| transfer learning 手滑 Dense(5) | CIFAR-10 是 10 类 |
| `preprocess_input` 没赋值 | 函数返回新数组，必须 `x = preprocess_input(x)` |
| 解冻 `[:-14]` 逻辑反了 | `[:-14]` 是前 N-14 层，要的是 `[-14:]` |
| 特征提取阶段过拟合 | 分类头容量不够，微调解冻后好转 |
