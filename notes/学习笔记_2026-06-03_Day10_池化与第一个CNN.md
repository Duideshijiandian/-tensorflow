## 二、池化（Pooling）的动机

### 问题起点

一张 28×28 的 MNIST 图片，经过 16 个 3×3 卷积核（valid padding）后：
- 输出尺寸：`(26, 26, 16)` = **10,816 个值**
- 原始图片才 784 个像素——卷积后数据反而膨胀了！

如果每一层都这样膨胀，几层之后参数量直接爆炸。需要一种方式**压缩特征图，同时保留最重要的信息**。

### 类比：看卫星地图

| 操作 | 类比 |
|---|---|
| 卷积 | 用小窗口仔细扫过每个角落，标注"这里像屋顶""这里像墙壁" |
| 池化 | 把地图分成 2×2 格子，每个格子只保留"信号最强"的标注，扔掉其他三个 |

代价：丢掉了"房子在格子左上还是右下"的精确位置信息。
收获：保留了一个更紧凑的"这附近有房子"的摘要。

## 三、MaxPooling 手动验证

### 输入：4×4 矩阵

```
 1    4   -5    3
 2   -1    0    6
-3    7    8   -2
 5   -4    9    1
```

### 2×2 MaxPooling (stride=2, valid padding)

分成四个不重叠的 2×2 窗口：

| 窗口 | 覆盖的值 | Max |
|---|---|---|
| 左上 (0-1, 0-1) | 1, 4, 2, -1 | **4** |
| 右上 (0-1, 2-3) | -5, 3, 0, 6 | **6** |
| 左下 (2-3, 0-1) | -3, 7, 5, -4 | **7** |
| 右下 (2-3, 2-3) | 8, -2, 9, 1 | **9** |

输出：2×2 的矩阵 `[[4, 6], [7, 9]]`

首次运行代码时输出和手动计算**不一致**——因为前面还套了一层 Conv2D，随机初始化的权重导致特征图上的值已经不是原始矩阵了。

### 修正：去掉 Conv2D，直接 Pooling

把 Conv2D 删掉，让 4×4 矩阵直接喂给 MaxPooling2D，验证结果和手算完全一致 ✅

## 四、Max Pooling vs Average Pooling

### 具体例子

对一个 2×2 区域 `[[0.1, 0.9], [0.0, 0.8]]`：

| 方法 | 结果 | 在说什么 |
|---|---|---|
| Max Pooling | **0.9** | "这个区域里**有**特征！信号很强！" |
| Average Pooling | **0.45** | "整体来说特征不太强，马马虎虎 0.45" |

三个弱信号（0.1, 0.0, 0.8）把那个最强的 0.9 "稀释"了——这正是 Average Pooling 的缺点。

### 选择逻辑

| | Max Pooling | Average Pooling |
|---|---|---|
| 关心什么 | "特征**有没有**出现？" | "特征**整体有多强**？" |
| 适合场景 | 边缘、角点、纹理——信号**稀疏但尖锐** | 整体色调、平滑渐变——信号**密集且均匀** |
| 翻译 | 宁可错报，不可漏报 | 不追求单个亮点，追求全局印象 |

CNN 里 Max Pooling 是默认选择——用"最强的那个激活"代表整个区域，对平移和微小偏移也更鲁棒。

## 五、关键发现：卷积层之间必须加激活函数

### 问题

搭建 CNN 时，两个 Conv2D 都没写 `activation='relu'`。

### 为什么这是错的？

1. 卷积运算 `W*x + b` 是**线性**运算
2. 两个线性变换的复合，整体**仍然是线性的**（等价于一个大的 `W'*x + b'`）
3. 所以两层卷积等于一层——第二层白搭了

这跟 Day 3 学激活函数时的结论完全一致：**没激活函数，不管叠多少层，本质都是一层。**

### 修正

两个 Conv2D 全部加上 `activation='relu'`。

注意：MaxPooling 不需要单独加激活函数——"取最大值"本身已经是非线性操作。

## 六、第一个 CNN 架构

### 完整 shape 流程

```
Input              (28, 28, 1)       ← MNIST 灰度图
    ↓
Conv1 (4×3×3, ReLU) (26, 26, 4)     ← 检测横竖撇捺
Pool1 (2×2)         (13, 13, 4)     ← 压缩一半
    ↓
Conv2 (8×3×3, ReLU) (11, 11, 8)     ← 组合低级特征
Pool2 (2×2)         ( 5, 5, 8)      ← 再压缩
    ↓
Flatten             200              ← 拉成向量
    ↓
Dense(100) → ReLU   100              ← 隐藏层
    ↓
Dropout(0.2)                          ← 正则化
    ↓
Dense(10)           10               ← 分类输出（logits）
```

### 设计决策

| 决策 | 选择 | 原因 |
|---|---|---|
| Conv1 filter 数 | 4 | 横竖撇捺——4 个基础方向 |
| Conv2 filter 数 | 8 | 组合低级特征，通常翻倍 |
| Pooling 次数 | 2 次 | 1 次不够压缩，2 次刚好 |
| 隐藏 Dense 单元 | 100 | 中间过渡，在 Flatten(200) 和 输出(10) 之间 |
| Dropout 比例 | 0.2 | 训练时随机丢弃 20% 神经元 |

---

## 七、Dropout 到底影响谁？

### 问题

`Dense(100) → ReLU → Dropout(0.2) → Dense(10)` — Dropout 影响前面一层还是后面一层？

### 分析

用流水线类比：`厨师(Dense100) → 服务员(Dropout) → 顾客(Dense10)`

服务员摔掉菜（随机清零），**吃不到菜的是顾客**——Dense(10) 看到的输入被改了。

| 视角 | 影响谁？ |
|---|---|
| **前向传播**（数据流） | **后面**——下一层收到的值被改写了 |
| **正则化**（学习效果） | **前面**——强迫前面一层的神经元独立工作，不能互相依赖 |

### 结论

- Dropout 放在哪一层**后面**，就正则化**那一层**
- 训练时随机清零 → 测试时 Dropout 自动关闭 → 全部神经元一起工作

## 八、训练结果

```
训练集 loss: 0.064
测试集 loss: 0.049
准确率: 98.3%
```

### 有意思的现象：测试 loss 比训练 loss 还低

通常训练 loss 更低，但这里反过来了——**这正是 Dropout 在正常工作**：

| 阶段 | Dropout | 效果 |
|---|---|---|
| 训练 | 随机扔掉 20% 神经元 | 网络变"笨"，loss 偏高 |
| 测试 | 自动关闭 | 全部 100 个神经元一起干活，loss 更低 |

### 对比 Day 6 的纯 Dense 网络

| | 纯 Dense | 第一个 CNN |
|---|---|---|
| 准确率 | ~97% | **98.3%** |
| 参数量 | 很大（全连接） | 很小（参数共享） |
| 只用几个 filter | — | 4 + 8 = 12 个 |

CNN 只用极少的参数就超越了全连接网络——这就是卷积的威力。

## 九、遇到的问题和解决过程

### 问题 1：3×3 特征图塞进 2×2 池化窗口

- **现象：** Conv2D 输出 3×3，MaxPooling2D(2×2, stride=2) 怎么算？卡住了
- **原因：** 3×3 只能放一个完整的 2×2 窗口（第 0-1 行，第 0-1 列），往右或往下移 2 步都会越界
- **解决：** 公式 `floor((3-2)/2) + 1 = 1`，输出 1×1。3×3 经过 2×2 Pooling(stride=2) 只有一个值

### 问题 2：Conv2 输出 channel 算错——8 写成 32

- **现象：** 推导 shape 时 `Conv2(8, 3×3)` 的输入 `(13, 13, 4)`，输出写成了 `(11, 11, 32)`
- **原因：** 把第一层 filter 数(4) 和第二层 filter 数(8) 乘起来了
- **纠正：** 输出 channel **只**等于这一层的 filter 数量，跟上一层无关。正确输出：`(11, 11, 8)`

### 问题 3：`reshape(-1, 28, 28, 1)` 里的 `-1` 是什么？

- **问题：** 为什么写 -1 而不是 60000？
- **答案：** `-1` 表示"自动推算这一维"。总元素数 ÷ 已知各维乘积 = 第一维大小
  - 训练集：47040000 ÷ (28×28×1) = 60000
  - 测试集：7840000 ÷ (28×28×1) = 10000
- **好处：** 代码通用——不管来多少张图，shape 都对

### 问题 4：MNIST 是 `(60000, 28, 28)` 但 Conv2D 要 `(batch, 28, 28, 1)`

- **现象：** `cnn1.py` 里没 reshape，直接 `(60000, 28, 28)` 喂给 Conv2D，竟然没报错
- **原因：** TensorFlow 内部自动补了缺失的 channel 维度
- **结论：** 能用但不推荐依赖——应该显式 `reshape(-1, 28, 28, 1)`，自己掌控 shape

### 问题 5：卷积层之间没有激活函数

- **现象：** 两个 Conv2D 都没写 `activation='relu'`
- **后果：** 两个线性变换叠在一起 = 一个线性变换，第二层白搭
- **解决：** 每层 Conv2D 都加上 `activation='relu'`，引入非线性

## 十、代码产出

`cnn2.py`：第一个完整的 CNN

```python
# 核心架构
model = tf.keras.Sequential([
    Conv2D(4, 3×3, activation='relu', input_shape=(28, 28, 1)),
    MaxPooling2D(2×2),
    Conv2D(8, 3×3, activation='relu'),
    MaxPooling2D(2×2),
    Flatten(),
    Dense(100), ReLU(),
    Dropout(0.2),
    Dense(10)  # from_logits=True, 不加 softmax
])
```

## 十二、比赛相关——AI 支持的自主学习

**今日体现的 AI 引导学习模式：**

1. **理解动机先于操作：** 先问"卷积后数据膨胀了怎么办？"引出池化的必要性，而不是直接讲 MaxPooling2D 怎么用
2. **手动验证 vs 盲目信任代码：** 让学生自己写 4×4 矩阵手动算 Pooling，然后和代码输出对比——发现"不一致"的那一刻才是真正的学习（因为前面套了 Conv2D）
3. **错误是教学工具：** 两个 Conv2D 都没加激活函数——这不是疏忽，而是故意留的判断空间。学生自己推演出"两层线性=一层线性"，比被告知 100 次都深刻
4. **类比降低认知负荷：** 用"食堂阿姨算菜"解释 `-1`，用"服务员摔菜"解释 Dropout——把抽象概念翻译成生活经验

**可作为比赛案例的素材：**
- 手动计算 vs 代码验证的闭环——从"相信代码"到"验证代码"的思维转变
- 架构设计决策的记录（filter 数量选择、为什么两层卷积、为什么加池化）
- 遇到 5 个问题、逐一排查解决——展示完整的"学→做→卡→推→通"学习循环
