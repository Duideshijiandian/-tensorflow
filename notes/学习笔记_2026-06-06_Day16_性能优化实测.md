# Day 16: tf.data 性能优化实战

**日期：** 2026-06-06

## 探索：num_parallel_calls（多线程并行映射）

### 问题

`.map()` 默认一次只处理一张图，CPU 多核白白闲置。直觉上——用多个核心并行处理应该更快。

### 尝试

```python
Dataset1 = Dataset1.map(preprocess, num_parallel_calls=tf.data.AUTOTUNE)
```

### 结果

epoch 时间反而**变长**了。

### 原因分析

`preprocess` 函数里的操作太轻了：
- `resize`（32→96）：~1ms
- `preprocess_input`（减均值除方差）：<1ms

并行不是免费的——创建线程、分配任务、同步结果需要开销。相当于：
> 雇了 4 个工人搬一根牙签，喊人排队的时间比干活长。

### 什么时候值得并行？

| 场景 | 适合并行？ |
|---|---|
| 轻量操作（数学运算、小图 resize） | ❌ 管理开销 > 计算收益 |
| 重型 IO（读硬盘文件、解码 JPEG） | ✅ 释放其他核心做 IO |
| 复杂增强（随机裁剪、颜色变换） | ✅ 计算密集 |
| 远程数据读取 | ✅ 等待网络时并行 |

### 核心教训

> **优化不能靠猜，要实测。** 凭直觉加的东西，跑出来的结果才说了算。

## 当前最优管道

```python
from_tensor_slices → map(preprocess) → shuffle → batch → prefetch
```

- 不加 `num_parallel_calls`（实测单线程更快）
- 测试集不加 `shuffle`
- `prefetch(tf.data.AUTOTUNE)` — 这一步实际有效，让 CPU/GPU 并行
