## 二、Day 11：CIFAR-10 第一个 CNN

### 2.1 从 MNIST 到 CIFAR-10

| | MNIST | CIFAR-10 |
|---|---|---|
| 图片尺寸 | 28×28×1 | 32×32×3 |
| 图片类型 | 灰度手写数字 | 彩色真实物体 |
| 类别 | 10 种数字 | 10 种物体（飞机、汽车、鸟、猫、鹿、狗、青蛙、马、船、卡车） |
| 难度 | 入门级 | 明显更难 |

### 2.2 第一个架构 + 初始结果

```
Conv2D(128, 3×3) → ReLU → MaxPool(2×2)
Conv2D(256, 3×3) → ReLU → MaxPool(2×2)
Flatten → Dense(128) → ReLU → Dropout(0.3) → Dense(10)
```

- 准确率：**~70%**
- 训练 loss：0.5，测试 loss：0.8，**gap = 0.3**——明显过拟合

### 2.3 filter 数量讨论

filter 从 MNIST 的 4→8 跳到 CIFAR-10 的 128→256，增加了 30 多倍。

**直觉："通道变彩色了所以需要更多 filter"**——方向对但不够精确。

| 真正原因 | 说明 |
|---|---|
| 任务复杂度 ↑ | MNIST 检测笔迹粗细/倾斜，CIFAR-10 要检测颜色/姿态/背景/光照/遮挡 |
| 要检测的东西变多了 | 猫、飞机、卡车……每种物体的"特征"完全不同 |
| 不是通道数本身 | 灰度 CIFAR-10（1 通道）依然比彩色 MNIST（3 通道）更难 |

## 三、系统性瓶颈诊断——今日核心方法

**一个工程师和一个调参侠的区别：停手、思考、做对照实验。**

### 实验链

| 实验 | 做了什么 | 结果 | 结论 |
|---|---|---|---|
| 1 | 砍 filter：128→32, 256→64 | 准确率 67.4%（仅 ↓2.6%） | ✅ **卷积层不是瓶颈**（参数量 1/16，准确率几乎不变） |
| 2 | 加 Dense 神经元：128→512 | 准确率 70%→74%（↑4%） | ✅ **全连接层是瓶颈**（9216 维压到 128，太剧烈） |
| 3 | 加更多隐藏层 | 准确率没变化 | ✅ **深度不是瓶颈**（对全连接层来说） |
| 4 | 训练 loss vs 测试 loss | gap = 0.3 | ✅ **过拟合——不是容量问题，是泛化问题** |

### 方法论

```
怀疑某处是瓶颈 → 改变它 → 观察准确率变化
  ├── 变化大 → 确实是瓶颈 → 加大
  └── 变化小 → 不是瓶颈 → 不改，排查别处
```

这比"感觉这里不够就往上加"高效 10 倍。

## 四、Day 12：数据增强

### 4.1 为什么要增强

模型训练 loss 0.5、测试 loss 0.8、gap 0.3——**在背答案，不是真学会。**

Dropout 和 EarlyStopping 只"限制网络"，但数据还是那 50,000 张原图——翻来覆去看 5 遍，再笨也能背下来。

### 4.2 核心思想

**每一轮喂给模型的"同一张图"都长得不一样。** 相当于 50,000 张图 × N 种变体 = 近乎无限的数据。

### 4.3 TensorFlow 实现

```python
tf.keras.layers.RandomFlip()       # 随机翻转
tf.keras.layers.RandomRotation()   # 随机旋转
tf.keras.layers.RandomZoom()       # 随机缩放
```

放在模型的**最前面**——只在训练时随机变换，推理时自动关闭。

### 4.4 关键决策：选哪些增强？

**垂直翻转 vs 水平翻转**

| | 水平翻转 (HorizontalFlip) | 垂直翻转 (VerticalFlip) |
|---|---|---|
| 汽车 | ✅ 车头朝左/右都正常 | ❌ 轮子朝天——车祸现场 |
| 猫 | ✅ 猫朝左看/朝右看都正常 | ❌ 四脚朝天——猫不会这样站 |
| 飞机 | ✅ 朝左飞/朝右飞都正常 | ❌ 驾驶舱朝下——空难 |
| 船 | ✅ 船头朝左/朝右都正常 | ❌ 船底朝天——沉船 |

**规律：水平翻转保留"自然"，垂直翻转破坏重力。**

不是所有变换都合理——要看你数据的物理意义。

### 4.5 旋转参数的单位

⚠️ `RandomRotation(factor)` 的参数**不是角度**！

```python
factor=0.1  →  ±0.1 × 180° = ±18°   ✅
factor=15   →  ±15 × 180° = ±2700°  ❌ 图片变成抽象画
```

### 4.6 结果与反思

**增强前 → 增强后（epoch=5）**

| | 预测 | 实际 |
|---|---|---|
| 训练 loss | ↑ | ✅ ↑ 0.5 → 0.98 |
| 测试 loss | ↓ | ❌ 没降 |
| gap | ↓ | ✅ 减小了 |
| 准确率 | — | **反而降了** |

**预测对了一半，漏了一个关键变量：epoch 数。**

增强让任务变难了——相当于面对无穷多种变体。同样 5 个 epoch，原来能"背"完 50,000 张图，现在连每张图的几个变体都没见全。

### 4.7 修正：增加 epoch（5→15）

```
训练 loss：0.98 → 0.67（继续在降）
测试 loss：卡在 ~0.80（不降了）
gap：0.3 → 0.13 ✅ 缩小超一半
```

**过拟合被大幅压制了。** 但出现了新问题——测试 loss 卡在 0.8 **不再下降**。不再是过拟合，而是**够不着**。

## 五、BatchNormalization——打破 0.8 天花板

### 5.1 类比：流水线质检

```
原料 → 切割 → 打磨 → 喷漆 → 组装 → 成品
```

问题：切割工人今天输出 0~10cm，明天输出 0~100cm——后面每一道工序都被前面牵着鼻子走。

BN = 每一道工序后面加一个**质检员**——不管输入是什么范围，全部标准化到均值 0 方差 1。

### 5.2 三个效果

| 效果 | 为什么 |
|---|---|
| 训练变快 | 每层收到稳定输入，可用更大学习率 |
| 减轻梯度消失 | 值不会极端化，梯度稳定回传 |
| 自带一点正则化 | batch 内统计波动引入随机扰动 |

### 5.3 放置位置

**关键问题：BN 放激活函数前还是后？**

正确答案：**Conv → BN → ReLU**

原因：
- ReLU 把负值清零 → 如果 BN 在 ReLU 后，BN 会把"均值拉到 0"（压低了有用正信号）
- Conv 输出是线性值 → BN 先标准化 → ReLU 再做非线性截断 → 合理

### 5.4 结合 padding='same'

| padding='valid' | padding='same' |
|---|---|
| 每层 Conv 缩 2 格 | 卷积后尺寸不变 |
| 32→30→28→…→6×6 | 32→32→16→8 |

CIFAR-10 才 32×32，`valid` 缩太快了——`same` 给网络更多空间消化特征。

### 5.5 结果

```
BN + padding='same'：准确率 67% → 73%（↑6 个点）
```

但 val_loss 剧烈波动：

```
Epoch 7:  0.90
Epoch 8:  0.82  ← 最佳
Epoch 9:  1.21  ← 暴走
Epoch 10: 0.90
```

学习率 0.001 太大——BN 让曲面平滑了，但步子迈太大反而冲过谷底。调到 0.0005 依然波动——**不是学习率的问题，是网络太浅。**

### 排除了所有变量，剩下的是答案

## 七、遇到的问题和解决过程

### 问题 1：GPU 为什么这么慢？

- **现象：** 每次运行都有 WARNING 说 PTX JIT 编译可能要 30 分钟
- **原因：** RTX 5060 是 Blackwell 架构（compute capability 12.0a），TensorFlow 2.21 缺少预编译 kernel
- **真相：** 警告每次都打印，但实际编译结果被 NVIDIA 驱动缓存了——第二次运行会快很多
- **额外发现：** 数据增强（RandomFlip/Rotation/Zoom）在 CPU 上做，CPU↔GPU 搬运也是瓶颈

### 问题 2：WSL 有 GPU，Windows 原生没 GPU

- **现象：** 两个终端——WSL 跑 19s/epoch，PowerShell 跑 42s/epoch
- **原因：** TensorFlow ≥2.11 在 Windows 原生不支持 GPU，必须走 WSL2
- **解决：** 后续全部在 WSL 里训练

### 问题 3：准确率计算 bug

```python
# ❌ test_labels[i] 形状是 (1,)，if [False] 也是 True！
if jieguo[i] == test_labels[i]:

# ✅ 正确写法
if jieguo[i] == test_labels[i][0]:
```

### 问题 4：数据增强后准确率不升反降

- **做了：** 加 RandomFlip + RandomRotation + RandomZoom
- **预测：** test loss 会下降
- **结果：** test loss 没降，准确率还掉了
- **原因：** 漏了"epoch 不够"这个变量——增强让任务变难，需要更多轮次
- **修正：** epoch 从 5 加到 15，gap 从 0.3 缩小到 0.13

### 问题 5：val_loss 剧烈波动

- **现象：** 加了 BN 后 val_loss 在一个 epoch 从 0.82 崩到 1.21
- **初判：** 学习率太大
- **调后：** lr 降到 0.0005 依然波动
- **根因：** 2 层卷积不够深——网络在"硬记"训练集，每次记住一批，下一批推翻重来

### 问题 6：3×3 特征图 + 2×2 Pooling（Day 10 遗留）

- **现象：** Conv 输出 3×3，MaxPooling(2×2, stride=2) 怎么算？
- **答案：** `floor((3-2)/2) + 1 = 1`，输出 1×1
- **教训：** 推导 shape 时考虑边界情况

### 问题 7：两层线性卷积 = 一层线性

- **现象：** 两个 Conv2D 都没写 `activation='relu'`
- **后果：** 两个线性变换复合还是线性变换——第二层白搭
- **解决：** 每层加 activatoin='relu'，MaxPooling 不需要（"取最大值"本身就是非线性）

### 问题 8：Dropout 影响前一层还是后一层？

- **答案：**
  - 前向传播（数据流）：影响**后面**——下一层收到的值被改了
  - 正则化（学习效果）：影响**前面**——强迫前面一层神经元独立工作

## 八、代码产出

### 最终架构（Day 11-12 末）

```python
model = tf.keras.Sequential([
    # ===== 数据增强（仅训练时生效）=====
    RandomFlip("horizontal"),
    RandomRotation(0.05),        # ±9°
    RandomZoom(0.05),
    
    # ===== 卷积层 =====
    Conv2D(64, 3×3, padding='same'),
    BatchNormalization(),
    ReLU(),
    MaxPooling2D(2×2),
    
    Conv2D(128, 3×3, padding='same'),
    BatchNormalization(),
    ReLU(),
    MaxPooling2D(2×2),
    
    # ===== 分类器 =====
    Flatten(),
    Dense(512), ReLU(),
    Dense(10),                    # from_logits=True
])
```

### 最佳结果

- 准确率：~73%
- val_loss 最低：~0.82
- gap：~0.13（从 0.3 大幅缩小）

## 十、明日方向：Day 13 加第三层卷积

今天排除了所有变量，唯一没变的瓶颈是**网络深度**。

三层经典架构：
```
Conv(32) → BN → ReLU → Pool   (16, 16, 32)
Conv(64) → BN → ReLU → Pool   ( 8,  8, 64)
Conv(128) → BN → ReLU → Pool  ( 4,  4, 128)
Flatten → 2048
Dense(256) → ReLU → Dropout → Dense(10)
```

filter 从 32 起步——因为已经证明了 filter 数量不是瓶颈。

## 十一、比赛相关——AI 支持的自主学习

### 今日体现的学习模式

**1. 对照实验思维——科学方法的体现**

当准确率卡在 70%，没有盲目堆层数，而是设计了 5 个对照实验逐个排查瓶颈。这比传统的"老师告诉你哪里有问题"更深刻——**自己发现瓶颈的那一刻，知识真正内化了。**

**2. 预测 → 验证 → 纠错循环**

数据增强时先预测三个指标的变化方向，跑完发现"测试 loss 没降"——不是预测本身错了，而是漏了 epoch 这个隐藏变量。**"预测对了一半"比"没预测直接做"学到的东西多得多。**

**3. 错误是教学工具**

- 垂直翻转的讨论——不是直接说"不对"，而是让学生自己在脑子里模拟每种类别倒过来的样子
- 两层 Conv 没激活函数——故意留的判断空间
- 准确率计算 bug——数字看起来对但其实是假的

**4. 设计决策有记录、有理由**

每个架构选择都有"为什么"：
- filter 32/64 而不是 128/256——因为实验证明了 filter 不是瓶颈
- padding='same'——因为 32×32 经不起 valid 缩
- BN 放 ReLU 前——因为有推理过程支撑

### 可作为比赛案例的素材

1. **系统性诊断方法**：怀疑 → 设计对照实验 → 排除 → 定位 → 解决——完整的科学思维链条
2. **预测-验证-纠错**：先预测数据增强的效果，再验证，再分析偏差原因
3. **从"感觉"到"证据"的转变**：不再说"我觉得应该加 filter"，而是"实验排除了 filter 是瓶颈"
4. **完整的问题日志**：8 个真实问题的排查和解决过程，展示"学→做→卡→推→通"的学习循环
5. **技术决策树**：面对卡在 70% 这个具体问题，画出了一棵决策树（过拟合？→ 增强 → 容量？→ 加点 → 深度？→ 明天）
