# Day 15: tf.data 构建数据管道

**日期：** 2026-06-06

## 核心概念

### 为什么需要 tf.data？

之前 `model.fit(train_images, train_labels)` 的瓶颈：
- 一次性加载全部数据到内存（数据量大时不行）
- CPU 准备数据时 GPU 空闲，GPU 计算时 CPU 空闲

### 流水线思维（Pipeline）

```
from_tensor_slices → map(预处理) → shuffle(打乱) → batch(分批) → prefetch(预取)
```

每步独立、可替换、按顺序流下去。

### 各步骤详解

| 步骤 | 作用 | 关键点 |
|---|---|---|
| `from_tensor_slices` | 按第0维切片，一一配对 images[i]↔labels[i] | 不保证正确性，需要提前对齐 |
| `map` | 对每个元素独立处理（归一化、resize、数据增强） | batch 之前的 map 处理的是单张图 |
| `shuffle(buffer_size)` | 从缓冲区随机抽取，打乱顺序 | buffer 越大越随机，常设 1000~数据总量 |
| `batch(size)` | N 个一组打包 | 最后一批可能不满，`drop_remainder=True` 可丢弃 |
| `prefetch` | GPU 训练时 CPU 提前准备下一批 | 最后一步，用 `tf.data.AUTOTUNE` 自动调 |

### prefetch 的工作原理

```
无 prefetch（同步）：
│ CPU 准备 batch1 │→│ GPU 算 batch1 │→│ CPU 准备 batch2 │→│ GPU 算 batch2 │

有 prefetch（异步）：
│ CPU 准备 batch1 │→│ CPU 准备 batch2 │→│ CPU 准备 batch3 │
                    │ GPU 算 batch1  │→│ GPU 算 batch2  │→│ GPU 算 batch3  │
```

## 今日踩坑记录

| 坑 | 现象 | 原因 | 教训 |
|---|---|---|---|
| 测试集 shuffle | 准确率 10.24% ≈ 随机猜 | 预测顺序被打乱，跟原始标签对不上号 | **测试集永远不要 shuffle** |
| Python `and` 运算符 | preprocess 结果被丢弃 | `a and b` 返回 b，不是两个都执行 | 函数组合用 `def` 逐个调用，不用逻辑运算 |
| 微调学习率太大 | val_loss 暴涨，val_accuracy 崩到 45% | lr=0.0005 踹飞预训练权重 | **微调 lr = 特征提取 lr × 0.1~0.01** |

## 关键代码片段

```python
def preprocess(image, label):
    image = tf.image.resize(image, (96, 96))
    image = tf.keras.applications.mobilenet_v2.preprocess_input(image)
    return image, label

train_ds = tf.data.Dataset.from_tensor_slices((train_images, train_labels))
train_ds = train_ds.map(preprocess).shuffle(5000).batch(64).prefetch(tf.data.AUTOTUNE)

test_ds = tf.data.Dataset.from_tensor_slices((test_images, test_labels))
test_ds = test_ds.map(preprocess).batch(64).prefetch(tf.data.AUTOTUNE)  # 不 shuffle！

model.fit(train_ds, epochs=5, validation_data=test_ds)
```
